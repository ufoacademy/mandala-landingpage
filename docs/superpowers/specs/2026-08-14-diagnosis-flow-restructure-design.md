# 건강만다라 진단 플로우 재구성 — 동의 선이동 & 프리미엄 다이렉트 설계 문서

날짜: 2026-08-14

## 배경

건강만다라(`index.html`)는 보건소·기업 등 기관에 배포될 예정이다. 기존 플로우는 "64문항 퀴즈 → 검진수치 입력 → 무료 결과 화면(레이더차트·CTA 3개) → '프리미엄 리포트 받기' 버튼 → 개인정보/동의 모달 → AI 리포트 생성"이었다. 즉 개인정보·동의는 진단이 다 끝난 뒤, 사용자가 별도로 원할 때만 수집됐다.

기관 배포 목적상 모든 진단 참여자를 리드로 확보해야 하므로, 개인정보·건강정보 동의와 기본정보 입력을 **진단 시작 전**으로 옮기고, 무료 1차 결과 없이 **바로 프리미엄 AI 리포트**로 이어지는 구조로 바꾼다. 이와 별개로 현재 로컬에 커밋되지 않은 상태로 이미 구현되어 있는 개인정보보호법 제23조 대응(동의 3분리: 개인정보 필수/건강정보 필수/마케팅 선택 — `lib/validateLead.js`, `api/generate-report.js`, `google-apps-script/lead-webhook.gs`)을 그대로 재사용한다.

CTA도 현재 3개(1:1 상담·건강칼럼 구독·인증방)에서 1개(건강칼럼 구독 = 건강이음 공식 채널)로 줄인다. 나머지 두 링크는 개인 채널·커뮤니티 톡방으로, 기관 배포 시점에는 노출하지 않는다.

## 목표

1. 진단을 시작하는 모든 사용자가 개인정보(필수)·건강정보(필수)·마케팅(선택) 동의와 기본정보(이름·나이·성별·연락처·이메일)를 퀴즈 시작 전에 1회 입력한다.
2. 퀴즈·검진수치 입력이 끝나면 무료 1차 결과 화면 없이, 처음에 입력한 정보를 그대로 사용해 자동으로 프리미엄 AI 리포트를 생성한다.
3. 검진수치는 계속 전항목 선택 입력이며, 입력량이 많을수록 리포트가 정교해진다는 안내를 강화한다. 진단 시작 전 화면에서 어떤 검진수치 항목을 준비하면 좋은지 미리 안내한다.
4. CTA 링크를 건강이음 공식 채널(`pf.kakao.com/_HlPnn`) 1개로 통일한다.
5. 백엔드(`api/generate-report.js`, Sheets 웹훅) 변경 없이 프론트엔드 흐름 재배치만으로 구현한다.

## 아키텍처 — 화면 흐름

```
SCREEN 1 (인트로, 마케팅 소개 유지, CTA 1개로 축소)
    └─[진단 시작하기 버튼]→
SCREEN 1.5 (신규: 동의 + 기본정보)
    ├─ 동의 체크박스 3개 (필수: 개인정보 / 필수: 건강정보 / 선택: 마케팅) — 작은 글자, 한 화면
    ├─ 기본정보 입력: 이름·나이·성별·연락처·이메일
    ├─ 검진데이터 사전 안내 박스: "다음 항목이 있으면 더 정확합니다 — BMI·허리둘레·혈압·공복혈당·HbA1c·중성지방·비타민D (없어도 진단 가능)"
    └─[필수 동의 2개 + 필드 유효성 통과 시 진단 시작 버튼 활성화]→
SCREEN 2 (퀴즈, 기존 동일, 64문항)
    →
SCREEN 3 (검진수치 입력, 기존 동일 + "입력하신 데이터가 많을수록 더 정확한 프리미엄 리포트가 생성됩니다" 안내 문구 추가)
    →
SCREEN 4 (간소화된 결과 화면)
    ├─ 8영역 레이더차트만 표시 (점수 요약카드·공유버튼 등 제거)
    ├─ CTA 1개 (건강이음 채널)
    └─ 자동으로 "AI가 리포트를 생성중입니다..." 로딩 상태로 전환 (사용자 클릭 불필요)
    →
api/generate-report.js 호출 (SCREEN 1.5에서 수집한 정보 + areaScores + checkupSummary + totalScore + lowScoreItems)
    →
report.html (프리미엄 리포트, 기존 그대로)
```

## 컴포넌트별 설계

### A. SCREEN 1 인트로 — CTA 축소

- `quick-cta-cards`(intro, 현재 3개: qc-1/qc-2/qc-3)에서 qc-1(1:1 상담, `open.kakao.com/me/healthteather`)과 qc-3(인증방, `open.kakao.com/o/pYYxjLpi`)를 제거하고 qc-2(건강칼럼 구독, `pf.kakao.com/_HlPnn`)만 남긴다.
- "진단 시작하기" 버튼(`startApp()`)의 동작 자체는 유지하되, 최종 목적지가 SCREEN 2가 아니라 신규 SCREEN 1.5가 되도록 변경한다.

### B. SCREEN 1.5 (신규) — 동의 + 기본정보

- 필드: 이름, 나이, 성별, 연락처, 이메일, 동의 체크박스 3개(개인정보 필수/건강정보 필수/마케팅 선택), 허니팟 필드.
- 기존 `premiumModal`(SCREEN 4에서 트리거되던 모달)에 있던 입력 필드·문구·검증 로직을 이 신규 화면으로 이동한다. 클라이언트 검증 규칙(`consentPersonal`, `consentHealth` 필수 체크)은 이미 로컬에 존재하는 `lib/validateLead.js` 로직과 동일한 기준을 프론트에서도 사용한다.
- 검진데이터 사전 안내 박스를 이 화면 하단에 추가한다: BMI·허리둘레·혈압·공복혈당·HbA1c·중성지방·비타민D 항목을 예시로 들고, 없어도 진단은 가능하다고 명시한다.
- 유효성 통과 시 수집한 값(name, age, gender, contact, email, consentPersonal, consentHealth, consentMarketing)을 JS 변수(또는 세션 상태)에 저장해두고, 이후 화면 전환에서 재입력받지 않는다. 기존 `premiumModal`(오버레이 모달)은 삭제하고, 그 안에 있던 입력 필드·문구·검증 로직만 SCREEN 1.5(일반 `.screen` — 다른 화면들과 동일한 전체화면 섹션)로 옮긴다. `openPremiumModal()`/`closePremiumModal()` 함수는 제거하고, SCREEN 1.5로의 이동은 다른 화면 전환과 동일하게 `.screen` 클래스 토글 방식을 따른다.

### C. SCREEN 2 (퀴즈), SCREEN 3 (검진수치 입력)

- 로직 변경 없음. SCREEN 3의 안내문(`checkup-hero`)에 "입력하신 데이터가 많을수록 더 정확한 프리미엄 리포트가 생성됩니다" 한 줄을 기존 "없는 항목은 비워두면 됩니다" 문구 뒤에 추가한다.

### D. SCREEN 4 (결과 화면) — 간소화 및 자동 진행

- 기존 점수 요약 카드, "카카오톡으로 공유하기"/"링크 복사하기" 버튼, CTA 카드 3개를 제거한다.
- 8영역 레이더차트(`showResults()`가 그리는 캔버스)만 유지하고, CTA 카드는 1개(건강이음 채널)만 남긴다.
- 사용자의 추가 클릭 없이, 레이더차트를 1.5초간 표시한 뒤 자동으로 "AI가 리포트를 생성중입니다..." 로딩 상태로 전환하고 `submitPremiumLead()`에 해당하는 로직(SCREEN 1.5에서 저장해둔 정보 + `collectAreaScoresForReport()`/`collectCheckupSummaryForReport()`/`collectTargetTableForReport()` 결과를 조합)을 자동 호출한다.

### E. 백엔드 — 변경 없음

- `api/generate-report.js`, `lib/validateLead.js`, `google-apps-script/lead-webhook.gs`는 현재 로컬에 미커밋 상태로 이미 구현되어 있는 3단계 동의 구조(`consentPersonal`/`consentHealth`/`consentMarketing`)를 그대로 사용한다. 이번 작업에서 백엔드 코드는 수정하지 않는다.
- 이번 변경으로 인해 "진단을 시작한 모든 사용자"가 리드로 기록되는 대상이 된다 (기존에는 프리미엄 신청자만 기록됨). 이는 기관 배포 목적에 부합하는 의도된 동작이다.

### F. 범위 밖 (이번 작업에서 하지 않음)

- 보건소/기업 대상 "사용권한 부여" — 로그인, 기관별 테넌트 분리, 접근 제어 등은 향후 별도 프로젝트로 남겨둔다.
- `index_backup_habitonly.html`(검진 없는 습관전용 버전으로 추정)은 이번 스코프에 포함하지 않는다.

## 테스트 관점

- `index.html`은 별도 JS 모듈로 분리된 로직(`lib/validateLead.js` 등)만 `node:test`로 단위 테스트되고, 화면 흐름 자체는 브라우저 수동 검증(`npx serve .`)으로 확인한다. 기존 프로젝트 관례를 따른다.
- 확인 항목: (1) 필수 동의 미체크 시 진단 시작 버튼이 막히는지, (2) SCREEN 1.5에서 입력한 정보가 최종 `POST /api/generate-report` 페이로드에 그대로 실리는지, (3) 검진수치를 하나도 입력하지 않아도 리포트 생성까지 끝까지 진행되는지, (4) CTA 링크가 인트로·결과화면 모두 1개씩만 남았는지.
