# 리드 저장용 Google Apps Script 배포 방법

## 검사별 인증코드 등록 (신규 흐름)

`exam-registration.gs`와 `registration-dialog.html`은 운영 시트에 연결된 **같은 Apps Script 프로젝트**에 추가합니다. 스크립트 속성 `STAFF_EMAILS`에 등록 담당자의 Google 계정 이메일을 쉼표로 구분해 설정합니다. 로그인 이메일을 읽을 수 없거나 목록에 없으면 등록과 재발급이 거부됩니다. 시트 접근 권한도 담당자로 제한하세요.

판매 채널은 **네이버 스마트스토어**와 **건강만다라 홈페이지** 두 곳으로 계획합니다. 각 채널이 열리기 전과 주문 연동 전에는 담당자가 해당 채널에서 결제 완료 상태, 신청자 이름·휴대폰 번호, 같은 주문의 기존 처리 여부를 직접 확인합니다. 결제가 확인된 주문 1건에 검사 1회를 등록하고, 채널별 주문번호와 발급한 신청ID의 대응을 담당자 전용 기록에 남겨 중복 발급을 막습니다. 현재 검사 신청 시트에는 주문번호를 저장하는 열이 없으므로 이 대응 기록은 별도로 관리해야 합니다.

등록 화면은 시트의 **검사 신청 → 새 검사 등록** 메뉴에서 엽니다. 첫 등록은 휴대폰 번호 하나에 사용자ID 하나를 발급하고, 재검사는 같은 ID로 새로운 신청ID와 인증코드를 발급합니다. 담당자가 **문자 내용 복사**를 눌러 검사코드와 진단 링크가 담긴 안내문을 해당 번호로 직접 발송합니다. 이 화면은 결제를 조회하거나 문자를 자동 발송하지 않습니다. 코드 원문은 시트에 저장되지 않으므로 분실하면 **해당 신청 코드 재발급**을 실행하고 새 코드가 포함된 안내문을 다시 보내세요. 새 코드 발급 즉시 이전 코드는 무효입니다.

신규 탭 헤더는 `앱사용자명단`: `사용자ID,이름,휴대폰번호,사용상태,등록일`, `검사신청`: `신청ID,사용자ID,이름,휴대폰번호,코드해시,상태,발급일,만료일,진단ID,검사완료일`입니다. 기존 탭에 다른 헤더가 있으면 등록 함수가 중단합니다. 기존 기록의 보존·이전 여부를 확인한 뒤 헤더를 맞춰야 합니다. `NEXT_USER_SEQUENCE` 스크립트 속성은 기존 ID 최댓값과 비교하여 자동 증가합니다.

이 등록 코드만 따로 배포해도 진단 시작과 결과 연결은 바뀌지 않습니다. 아래의 구형 운영 배포본 경고를 포함해 양쪽 GAS와 사이트/API를 함께 검증한 뒤 전환해야 합니다.

> 운영 API는 진단 저장 시 결과코드 해시의 저장 확인(`resultCodeStored: true`)과 서명된 쓰기를 요구합니다. 현재 저장소의 `lead-webhook.gs`는 이 운영 배포본과 동기화되지 않았으므로, 이 파일을 그대로 운영 Apps Script에 재배포하지 마세요. 운영 스크립트 원본과 대조해 동기화한 뒤 배포해야 합니다.

> **2026-08-19 업데이트:** `진단기록` 탭의 컬럼 구성이 바뀌었습니다 — 8영역 점수(%)는 **1~8위 약점 순위**(예: `1위 약점` 칸에 `휴 44%`)로, 검진수치는 JSON 문자열 한 칸이 아니라 **항목별 컬럼 29개**(미입력 항목은 공란)로 나뉩니다. 이미 배포해서 쓰고 있었다면 아래 "컬럼 구성이 바뀐 경우" 섹션을 꼭 읽어주세요 — 기존 헤더 행이 남아있으면 자동으로 갱신되지 않습니다.
>
> **2026-08-18 업데이트:** 진단 플로우가 "동의·기본정보를 진단 시작 전에 필수로 받는" 방식으로 바뀌면서, 시트 구조도 리드 탭(1개) + 1점문항추적 탭(1개)의 2탭 구조에서 **`진단기록` 탭 1개로 통합**되었습니다. 이미 예전 버전을 배포해서 쓰고 있었다면 아래 "기존 사용자 마이그레이션" 섹션을 먼저 읽어주세요.

## 새로 설정하는 경우

1. 리드를 저장할 새 Google Sheets 문서를 만듭니다. 탭은 따로 만들 필요 없습니다 — `진단기록`이라는 이름의 탭과 헤더 행을 스크립트가 첫 실행 시 자동으로 만듭니다.
2. 메뉴에서 **확장 프로그램 → Apps Script**를 클릭합니다.
3. 기본 코드를 지우고 `lead-webhook.gs` 내용을 붙여넣습니다.
4. 우측 상단 **배포 → 새 배포**를 클릭합니다.
5. 유형 선택에서 **웹 앱**을 선택합니다.
6. 설정:
   - 실행 계정: 나(본인 계정)
   - 액세스 권한이 있는 사용자: 모든 사용자
7. **배포**를 클릭하고 권한 승인을 완료합니다.
8. 발급된 **웹 앱 URL**을 복사합니다 (`https://script.google.com/macros/s/XXXX/exec` 형태).
9. 이 URL을 Vercel 프로젝트의 `SHEETS_WEBHOOK_URL` 환경변수로 등록합니다.

## 기존 사용자 마이그레이션 (예전 2탭 구조에서 업그레이드)

기존 스프레드시트의 첫 번째 탭(리드 시트)과 `1점문항추적` 탭은 **건드리지 않습니다** — 과거 데이터는 그대로 남아있고, 스크립트가 더 이상 거기에 쓰지 않을 뿐입니다.

1. Apps Script 편집기에서 기존 코드를 이 파일 내용으로 전부 교체합니다.
2. **배포 → 배포 관리 → 연필 아이콘(수정) → 새 버전** 순서로 기존 배포를 업데이트합니다 (URL이 바뀌지 않으므로 Vercel의 `SHEETS_WEBHOOK_URL`은 그대로 둬도 됩니다).
3. 스프레드시트를 열어보면 첫 실행 시 `진단기록`이라는 새 탭이 자동 생성됩니다. 기존 두 탭은 참고용으로 그대로 두거나, 필요 없으면 직접 삭제해도 됩니다.

## 컬럼 구성이 바뀐 경우 (2026-08-19)

`getOrCreateDiagnosisSheet()`는 시트가 **완전히 비어있을 때만** 헤더 행을 새로 씁니다. 즉 이미 `진단기록` 탭에 헤더+데이터가 남아있다면, 코드만 새로 배포해도 헤더 라벨이 예전 그대로라 새 컬럼 구성과 어긋납니다.

1. Apps Script 코드를 이 파일 내용으로 교체하고 **배포 → 배포 관리 → 새 버전**으로 갱신합니다.
2. 스프레드시트에서 `진단기록` 탭을 엽니다. 테스트로 넣어본 행(`test-id-1` 등)만 있고 실제 고객 데이터가 없다면 **탭 전체를 삭제**하세요 — 다음 요청이 들어올 때 새 헤더로 자동 재생성됩니다.
3. 이미 실제 고객 데이터가 쌓여있다면 탭을 삭제하는 대신, 헤더 행(1행)만 지우고 `buildDiagnosisHeader()` 실행 결과로 새로 채워 넣거나, 기존 탭 이름을 `진단기록_구버전`처럼 바꿔두고 스크립트가 새 탭을 만들게 하세요 (과거 데이터 보존).

## 데이터 흐름

- **진단을 완료하는 모든 사용자**: 결과 화면이 뜨는 순간 `type:"diagnosis"`로 전송되어 `진단기록` 탭에 한 행이 추가됩니다 — ID, 날짜, 이름/나이/성별/이메일/연락처/광고동의(진단 시작 전 필수 동의 화면에서 입력받은 값), 총점, **1~8위 약점 순위**(가장 약한 영역부터 `휴 44%`처럼 영역명+% 형식으로 8칸), 64개 문항별 응답값, **검진수치 항목별 컬럼 29개**(공복혈당·당화혈색소 등 — 입력하지 않은 항목은 공란).
- **프리미엄 리포트 생성이 완료된 사용자**: `type:"premium_lead"`로 전송되며, 새 행을 추가하는 대신 **같은 ID를 가진 진단 행을 찾아 리포트생성일 · AI리포트(JSON) 두 칸만 채워넣습니다** (업데이트). 매칭되는 행을 못 찾는 예외 상황이면 리포트 유실을 막기 위해 최소 정보(ID·날짜·리포트)로 새 행을 추가합니다.
- 즉 한 사용자당 원칙적으로 한 행만 생기며, 프리미엄 신청 여부는 "AI리포트(JSON)" 칸이 채워져 있는지로 구분할 수 있습니다.

## 동작 확인 (curl)

진단 완료 기록 확인:

```bash
curl -X POST "여기에_배포된_웹앱_URL" \
  -H "Content-Type: application/json" \
  -d '{"type":"diagnosis","id":"test-id-1","timestamp":"2026-08-18T00:00:00.000Z","name":"테스트","age":"35","gender":"f","email":"test@example.com","contact":"010-0000-0000","consentMarketing":true,"totalScore":160,"areaScores":[{"id":1,"pctVal":70},{"id":2,"pctVal":60},{"id":3,"pctVal":44},{"id":4,"pctVal":55},{"id":5,"pctVal":65},{"id":6,"pctVal":50},{"id":7,"pctVal":75},{"id":8,"pctVal":80}],"allAnswers":{"1-A-1":2},"checkupValues":{"bmi":22.5,"fbg":93}}'
```

같은 ID로 리포트 첨부 확인 (위 curl을 먼저 실행한 뒤):

```bash
curl -X POST "여기에_배포된_웹앱_URL" \
  -H "Content-Type: application/json" \
  -d '{"type":"premium_lead","id":"test-id-1","report":{"greeting":"안녕하세요"}}'
```

`진단기록` 탭에 `test-id-1` 행이 하나 생기고 (`1위 약점` 칸에 `휴 44%`, `BMI`/`공복혈당` 칸에만 값이 채워지고 나머지 검진 항목은 공란), 두 번째 curl 이후 같은 행의 리포트생성일·AI리포트(JSON) 칸이 채워지면 성공입니다.
