# 프리미엄 리포트 판매 연결 현황

2026-10-28

## 제작한 화면

- `/premium.html`: 판매 랜딩페이지, 3개 샘플 미리보기, 50,000원 → 9,900원, 이름·휴대폰 구매 입력 화면.
- `/promotion.html`: 온라인 플랫폼용 세로 홍보 시안과 소개문. 브라우저 인쇄로 PDF 저장 가능.
- `/api/payment-config`: 비밀키를 제외한 판매 준비 상태만 반환.
- `/api/create-premium-order`: 서버에서 가격을 9,900원으로 고정하고, 이름·휴대폰을 정규화해 서명한 요청을 주문 서비스에 전달하는 연결부. 실제 주문 저장 서비스·결제선생 청구·문자 발송은 아직 구현/연결되지 않음.

기존 진단 앱과 인증·데이터 저장 경로는 유지했다. 공개 배포나 운영 설정 변경은 하지 않았다.

## 확정된 사용자 흐름

1. 이름과 문자 수신 휴대폰 번호 입력, 개인정보 수집·이용 및 구매 안내 확인.
2. 서버에 `pending` 주문 생성. 서버 가격 9,900원, 상품 ID `mandala-premium` 고정.
3. 주문과 연결된 결제선생 청구 생성 → 고객 결제.
4. 서버에서 실제 수납 여부·금액·청구번호·주문번호 확인. 브라우저의 완료 URL이나 고객의 결제 완료 주장으로 권한 발급 금지.
5. 결제된 주문의 이름·정규화한 휴대폰으로 기존 사용자와 연결. 동명이인 또는 동일 번호 충돌은 자동으로 기존 기록에 병합하지 말고 확인 필요 상태로 처리.
6. 결제당 1개의 검사 초대 발급. 인증코드는 기존 초대의 해시 저장 규칙을 따른다.
7. 등록된 번호로 이름·인증코드·검사 링크 발송. 문자에는 검진수치나 습관 응답을 넣지 않는다.
8. 기존 `verify-user`에서 이름 + 휴대폰 + 인증코드가 일치해야 검사 허용.
9. 기존 진단 저장 경로가 사용자 ID와 초대 ID를 검사해 습관 DB에 연결.

## 결제선생에 확인할 사항

사업자 등록 완료와 API 이용 승인은 다르다. 공식 안내에 따르면 정식 서비스, 실제·예상 거래 규모, 연동할 서비스 자료 등을 검토하며 모든 신청에 즉시 API가 제공되지는 않는다.

- 안내: https://guide.payssam.kr/ko/articles/API-%EC%86%8C%EA%B0%9C--4ef317dc
- 개발자센터: https://developers.payssam.kr/
- 문의 내용: “건강만다라 온라인 리포트 9,900원 상품입니다. 이름·휴대폰 신청 후 주문별 청구 및 결제 확인 후 검사 이용권 문자 발송을 연동하려 합니다. API 제공 가능 여부, 테스트 계정, 청구 생성·결제 URL 조회·수납 조회·콜백 인증 방식·환불 명세를 안내해 주세요.”

승인 전에는 매니저에서 수동 청구·수납 확인·이용권 발송으로 운영할 수 있으나, 자동 결제 흐름과는 다르다. 현재 페이지는 수동 발송을 자동인 것처럼 표시하지 않고 판매 준비 상태를 보여준다.

## 남은 구현과 운영 설정

- 결제선생 승인 및 공식 API 명세 확보. 추측한 API 주소/인증 방식은 사용하지 않음.
- 내구성 있는 주문 DB와 주문번호 고유 제약. `pending → paid → invitation_issued → sms_sent` 상태 저장.
- 금액·상품·청구번호 서버 확인, 중복 수납 이벤트의 동일 주문 재처리 방지.
- 문자 발신번호 등록 및 문자 서비스 계정 연결. 초대 ID 기반 중복 발송 방지, 실패 재시도와 운영자 재발송.
- 문자/초대 발급 실패 시 결제 기록은 보존하고 재처리. 결제 재시도에서 이중 청구를 방지할 주문 재사용 정책.
- 환불·취소 시 미사용 초대 취소 및 사용 상태 정책 확정.
- 판매자 사업자 정보, 제공 시점, 환불 규정, 개인정보 처리자·보관기간·위탁사 확정. 건강정보 민감정보 동의는 기존 검사 단계에서 별도로 유지.
- 실제 테스트 결제 → 문자 → 인증 → 검사 저장까지 전 과정 확인 후 판매 오픈.

## 주문 서비스 연결 계약 (내부 설계, 결제선생 공식 API 아님)

`PREMIUM_ORDER_SERVICE_URL`로 POST. JSON 본문의 `HMAC-SHA256` hex를 `X-Mandala-Signature`로 전달한다. 수신 서버에서 본문 원문 서명과 생성 시각을 검증하고 주문 ID의 고유성을 보장해야 한다.

요청: `{type, orderId, name, phone, amount:9900, currency:"KRW", productId:"mandala-premium", consentVersion:"premium-v1", createdAt}`.

응답: `{orderId, amount:9900, checkoutUrl}`. 주문번호·금액·HTTPS·결제 도메인 허용 목록이 맞아야 브라우저에 반환한다. 이 응답은 수납 확인이나 검사 이용권이 아니다.

설정: `PREMIUM_SALES_ENABLED=false`를 기본값으로 유지. 위 구현·검증이 끝난 뒤에만 true. `PREMIUM_ORDER_SERVICE_URL`, 32자 이상 `PREMIUM_ORDER_SECRET`, `PREMIUM_CHECKOUT_ORIGIN`, `PREMIUM_TERMS_URL`, `PREMIUM_DELIVERY_DESCRIPTION` 필요. 비밀키를 브라우저 코드나 대화에 붙여넣지 않는다.

토스페이먼츠 전환 시 화면은 유지하고 주문 서비스의 결제 제공자와 수납 확인 부분을 교체한다.


## 결과 화면 / PDF 디자인 적용

- `index.html`의 검사 직후 화면에 실제 점수 8영역 카드 추가. 사용자 이름은 텍스트로만 삽입하며 인증·저장 흐름은 변경하지 않음.
- `result-theme.css`로 결과·TOP3 안내·프리미엄 버튼 디자인 적용. TOP3는 짙은 배경과 밝은 글자로 가독성 보완.
- `report.html`도 `report-theme.css`를 사용하므로 이후 실제 생성되는 리포트와 PDF에 보라색 카드 테마 적용.
- `/result-preview.html`은 공개 디자인 체험 페이지. 실제 검사 권한이나 사용자 데이터가 없으며 프리미엄 샘플로 연결.
- `/report-sample.html`과 `report-sample.js`는 별도의 공개 샘플. 실제 `premiumReport` 세션을 덮어쓰지 않음. 첨부 PDF의 예시 점수와 구성을 바탕으로 재구성한 디자인 샘플이므로 현행 POMP 점수와 구분 표시.
- 판매 페이지에 새 PDF 페이지 이미지 2종과 원본 PDF 이미지 2종 삽입. 원본 파일 자체는 수정하지 않음.
- 생성 PDF: `assets/report/premium-design-sample.pdf`, 11쪽. 실서비스 배포는 아직 하지 않음.
